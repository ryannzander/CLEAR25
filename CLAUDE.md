## Discoveries & Errors

- **Research Excel structure:** Research files use a single sheet (e.g. Toronto_ALL_Regression_ON_QC), headers on row 4, columns: Station ID, City, Distance (km), Direction, Tier, R, Slope, Intercept. No separate "All Stations Data" sheet for lat/lon. Coordinates are loaded from Canada NAPS Stations file (05. NAPS Stations/04. Canada_NAPS_Stations_Active_Years.xlsx) for NAPS IDs; US EPA station IDs get coords from legacy Excel if available, else remain None (WAQI live fetch will skip them).
- **Station filtering:** R ≥ 0.30 (methodology 2.3); skip non-numeric station IDs (header rows like "Rule 3 Québec Stations").
- **Thunder Bay (Rule 2):** NAPS 60807, 60809 injected into Toronto network; coords from NAPS file. Used for trigger only (>35 µg/m³); weak correlation with Toronto per methodology.
- **Public-facing numbers must match the methodology (fixed 2026-05-23):** The landing page shipped with figures found in NO project doc — "97.9% detection", "0% false alarms", "6–48hr" as a stat, "20 years", "218 stations", and "83 smoke events" (the "83" was a misread of **83.3%** = 2024 precision), plus per-city detection rates. Canonical source = `CLEAR_Methodology_ScienceFair Ver#1` + `CLEAR_Performance_Reference.docx` (matches the dashboard Research tab). **Historical (2003–2023, 21 seasons, 33 events):** 90.9% accuracy, 100% sensitivity (0 missed), 89.7% precision, 15.7h avg / 87h max lead, 36M+ obs, 309 NAPS + 131 U.S. EPA = 440 stations. **2024 out-of-sample (8 events):** 87.5% accuracy, 83.3% precision, 24.7h avg lead. The system is **Toronto-validated**; the 4 cities are *target* cities. Verify other surfaces (README, app) before quoting stats.
- **Live map only showed ~10–20 stations (fixed 2026-05-24):** Two stacked causes. (1) **Map regression** — commit `223f98f` made `updateMapMarkers` render only `results` (WAQI-confirmed, ~10) instead of the full `stations` catalog. Fixed in [app-map.js](webapp/dashboard/static/dashboard/app-map.js): always render the full catalog (gray = no current reading), color stations that have a live result, fall back to results only if `/api/stations/` failed. (2) **Catalog collapse** — `RESEARCH_DATA_BASE`/`NAPS_STATIONS_PATH` in [settings.py](webapp/ews/settings.py) pointed at `data/LAPTOP TSF 2026/`, but the real research data was moved to `projdata/` (gitignored, commit `6b0284d`). With the Excel path dead, the app fell back to `bundled_stations.json`, which held only **31 real stations** padded at runtime with ~140 **synthetic fake-coordinate** stations (`_expand_bundled_stations`, since removed). Fixes: settings now probes `projdata/` then `data/LAPTOP TSF 2026/`; the synthetic padding is gone; `bundled_stations.json` is **regenerated from the real research Excel** via [scripts/gen_bundled_stations.py](scripts/gen_bundled_stations.py) → **201 stations** (4 cities + Thunder Bay Rule 2). 138 have exact NAPS coords baked in; the 63 US-EPA stations (no coord file) are placed at runtime in `load_stations()` via `_derive_coord()` from city-center + distance + 16-point compass direction (same construction as the polar maps), tagged `coord_source="derived"`. `waqi.py` skips `derived` stations in live matching so an approximate position is never attributed a real monitor's reading (they still render, just without a live value). Production has no `projdata` and no `openpyxl` (slim Vercel reqs) → it serves the regenerated JSON; derivation uses only stdlib `math`/`json`. **Regenerate with `python scripts/gen_bundled_stations.py --write` whenever the research Excel changes.**
- **US station coordinates are exact, from EPA AQS (added 2026-05-24):** The 63 US-EPA stations initially had no coordinate source (placed by distance+direction approximation, no live data). Fixed by pulling exact lat/lon from the public EPA AQS sites file (`https://aqs.epa.gov/aqsweb/airdata/aqs_sites.zip`, auto-downloaded by the generator to `scripts/aqs_sites.zip`, gitignored). Our 9-digit US IDs are State(2)+County(3)+Site(4) = the AQS site key — all 63 matched. Now **201 stations = 134 NAPS + 67 EPA, 0 derived**, all exact and all WAQI-eligible (so US stations get live data). `coord_source` is `"naps"` (Canadian, circle marker), `"epa"` (US, diamond marker), or `"derived"` (rare fallback, dashed diamond, skipped in WAQI). `_bundled_coord_lookup()` in data.py lets the research-Excel path reuse the bundle's exact coords (Excel has no lat/lon), so local == production.
- **Security hardening pass (branch `feature/security-hardening`, 2026-05-28):** Settings: fail-closed when `SECRET_KEY` is missing in non-DEBUG, default `DEBUG=false`, require `DATABASE_URL` in prod, refuse to boot with the dev secret, drop wildcard `*.vercel.app` CORS and replace with scoped `VERCEL_HOST_PREFIX`, set `SECURE_SSL_REDIRECT` + HSTS + Secure/SameSite=Lax cookies, raise `MinimumLengthValidator` to 12, allauth tightened (`mandatory` email verification, no login/logout-on-GET, throttles via `ACCOUNT_RATE_LIMITS`), `DATA_UPLOAD_MAX_MEMORY_SIZE` set to 1 MiB. New `dashboard/middleware.py` adds `RequestSizeLimitMiddleware`, `SecurityHeadersMiddleware` (CSP + Permissions-Policy + COOP + CORP), and per-IP `RateLimitMiddleware` for unauthenticated mutating routes. CSRF re-enabled on every session-auth view (account profile/delete, plan downgrade, key create/revoke, checkout, suggestions/comments/votes) — kept exempt only on HMAC-signed and CRON_SECRET-gated externals. `@ensure_csrf_cookie` on render views + a tiny `app-csrf.js` fetch shim attaches `X-CSRFToken` automatically. Webhook now validates amount/currency, refuses to re-process terminal-status payments (idempotent), and extends `plan_expires` using `max(current, now) + days`. `Payment` got `currency` + unique opaque `order_id` (migration 0015). `RefreshToken` got a non-null FK to `APIKey`; revoking a key cascades to revoke its tokens; `verify()` rejects tokens whose key is inactive. JWT endpoints throttled per-IP and per-key. `APIKey.check_rate_limit` is now an atomic `SELECT … FOR UPDATE` + `F()` so the limit can't be exceeded under concurrency. `api_test_upgrade` returns 404 unless `DEBUG`. `health_check` only returns per-component diagnostics when the `X-Healthcheck-Token` header matches `HEALTHCHECK_TOKEN`. Account deletion now requires typing `DELETE MY ACCOUNT` in the body (UI gates the button). Cron/secret string compares routed through `hmac.compare_digest` via `timing_safe_token_compare`. `manage.py check` and `check --deploy` both clean.
