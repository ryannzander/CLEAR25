- **Refresh cadence drifted to ~1.5–2h instead of 30 min (addressed 2026-05-30, branch `fix/refresh-cadence`):** Not a code bug — GitHub Actions *scheduled* workflows are best-effort and routinely delayed or **dropped** under load, worst of all at the congested top/bottom of the hour, which is exactly what `*/30 * * * *` targeted. **Mitigation:** schedule at staggered off-peak minutes (`9,39 * * * *`) to cut GitHub's drop rate while keeping 30-min nominal spacing and staying under the free private-repo Actions budget (~1,440 min/month vs 2,000 free; each run ~30s but billed ≥1 min, so do **not** raise frequency past ~30 min or add in-job `sleep` loops — both blow the budget on a private repo). `/api/refresh/` is idempotent (`CachedResult.update_or_create`), so late/duplicate fires are harmless. **For a guaranteed 30-min cadence** GitHub's scheduler cannot promise it on any plan; point a free external cron (cron-job.org / UptimeRobot / Cronitor) at `https://clear25.xyz/api/refresh/` with header `Authorization: Bearer <CRON_SECRET>` and keep this workflow as backup. The repo is **private** (confirmed via unauthenticated GitHub API → 404), which is why minute budget matters.

- **ECCC RAQDPS run-discovery bug + grib mask (fixed 2026-06-09, branch `feature/eccc-ingest`):** `find_latest_raqdps` chose the forecast run by the highest numeric folder id (`sorted(...)[-1]` → always `12`).
